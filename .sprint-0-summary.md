# Sprint 0 — Indeed MCP Integration — Résumé d'implémentation

## Ce qui a été implémenté

- **`test_indeed.py`** : script de découverte et validation Indeed MCP
  - 7 phases : pre-flight → URL discovery → tools/list → test unitaire → scan deux passes → JSON output → rapport findings
  - Essaie automatiquement 4 URLs candidates et 6 noms de tools pour découvrir les paramètres réels
  - Tente 5+ combinaisons de paramètres (query/q/keywords, limit/maxResults, remoteJobsOnly/remote/f_WT…)
  - Logique Remote → Hybrid : passe 2 déclenchée si unique URLs < `HYBRID_THRESHOLD` (10)
  - Cap global 60 offres toutes passes confondues
  - Déduplication par URL entre les passes
  - Normalisation vers les 7 champs canoniques (url, title, company, location, description, job_type, date_posted)
  - Sortie rapport formaté pour copier dans `indeed_mcp_findings.md`
  - Exit 0 = OK, 1 = échec
  - Shebang : `#!/home/thehunter/venv/bin/python3`

- **`workflow-indeed-scan.json`** : workflow n8n complet
  - 10 nœuds : Schedule Trigger (cron 12:00) → Init Scan Roots → HTTP Request Remote (12 roots) → Aggregate Remote → IF Hybrid Needed → Branch hybrid (Build Queries → HTTP Request Hybrid → Merge Hybrid+Remote) / Branch passthrough → Merge Branches → Scan Output
  - Cap 60 et seuil hybrid 10 dans les Code nodes
  - Déduplication JS par URL dans chaque Code node d'agrégation
  - Extraction robuste des offres (tente 7 clés candidates : jobs/results/items/offers/data/jobResults/hits)
  - Auth via credential n8n de type `httpHeaderAuth` (Bearer token)
  - Import : `n8n import:workflow --input=workflow-indeed-scan.json` + `n8n publish:workflow`

- **`indeed_mcp_findings.md`** (Obsidian vault) : documentation complète
  - URLs candidates, paramètres candidats, structure réponse attendue
  - Commandes de déploiement VPS
  - Configuration credential n8n requise
  - Section "À valider" à remplir après exécution de `test_indeed.py` avec credentials réels

## Décisions clés

- **Découverte multi-pattern** : le serveur Indeed MCP n'est pas accessible sans credentials,
  donc `test_indeed.py` teste systématiquement plusieurs URLs, noms d'outils et noms de paramètres
  — le premier qui fonctionne est documenté et réutilisé.
- **Workflow n8n sans bibliothèque MCP** : utilise des nœuds HTTP Request standard pour appeler
  le protocole JSON-RPC 2.0 directement, évitant toute dépendance à un plugin n8n spécifique.
- **Branchement IF/Merge** dans le workflow pour garantir que la passe hybrid n'est déclenchée que
  si `remoteCount < 10`, conformément à la spec (pas d'appels API inutiles).
- **Extraction robuste des offres** : le Code node d'agrégation cherche l'array dans 7 clés
  (`jobs`, `results`, `items`, etc.) car la réponse réelle n'est connue qu'après exécution.
- **Shebang `/home/thehunter/venv/bin/python3`** : cohérent avec `test_sheets.py` (Sprint 0 précédent).

## Gotchas et contraintes découvertes

- **Credentials requis** : le serveur `mcp.indeed.com` retourne 404 sans authentification — impossible
  de valider les paramètres exacts sans clé API. Les sections "À valider" dans `indeed_mcp_findings.md`
  doivent être remplies après exécution de `test_indeed.py` sur le VPS.
- **Transport SSE possible** : si le serveur retourne `text/event-stream` plutôt que JSON direct,
  le script actuel ne parsera pas correctement. Solution : installer la bibliothèque Python `mcp`
  (`pip install mcp`) et basculer sur `sse_client`. Le script détecte cela via les erreurs de parsing.
- **Credential n8n** : le workflow référence `REPLACE_WITH_INDEED_MCP_CREDENTIAL_ID` dans les nœuds
  HTTP Request — à remplacer par l'ID réel après création du credential dans n8n.
- **Paramètre `f_WT`** : filtre interne Indeed (`f_WT=2` = remote, `f_WT=3` = hybrid). Non documenté
  officiellement, à confirmer. Si l'API MCP expose un paramètre nommé, il prime.
- **Pagination** : `PER_ROOT_LIMIT=30` suppose que l'API retourne jusqu'à 30 résultats par appel.
  Si la limite réelle est inférieure (ex. 10), le scan total sera < 60 même sans hybrid. À vérifier.
- **`/opt/apps/job-hunter/` inexistant** : créer le répertoire sur le VPS avant déploiement
  (`sudo mkdir -p /opt/apps/job-hunter && sudo chown thehunter:thehunter /opt/apps/job-hunter`).
