# Sprint 4 — Stockage Google Drive — Résumé d'implémentation

- `drive_uploader.py` — nouveau module standalone :
  - `build_yaml_header(metadata: dict) -> str` — frontmatter YAML (Company, Position, Offer URL, Detection date, Match Rate, Language, Status)
  - `prepend_yaml_header(content, metadata) -> str` — préfixe le header au Markdown
  - `build_telegram_notification(company, position, cv_url, lm_url, offer_url, job_id, application_type, form_questions_count) -> dict` — `{text, reply_markup}` avec boutons inline selon easy_apply vs form

    - `upload_document(content, filename, year_month) -> str` — upload vers Drive, permissions anyone/reader, retourne `webViewLink`

    - `_ensure_monthly_folder(year_month) -> str` — crée `job-hunter — Applications/{YYYY-MM}/` automatiquement
    - `update_matches(job_id, cv_url, lm_url) -> bool` — met à jour colonnes `cv_drive_link` (col 12), `letter_drive_link` (col 13), `status` (col 11) → "Généré"

  - `POST /store-documents` : prepend YAML header → upload CV + lettre → update MATCHES → build Telegram notification → return payload

## Décisions clés

- **Imports Google lazy** : `from google.oauth2... import ...` et `from googleapiclient... import ...` sont à l'intérieur des méthodes `DriveUploader` (`_get_drive`, `_get_gc`, `upload_document`). Pas d'import module-level → `import drive_uploader` ne casse pas si les packages ne sont pas installés. Tests patchent `_get_drive`/`_get_gc` directement, sans injection `sys.modules`.

- **Même service account** : `DriveUploader` utilise `credentials.json` pour Drive (via `google-api-python-client`) et pour Sheets (via `gspread`). Même path `GOOGLE_CREDS_PATH` / `/opt/apps/job-hunter/credentials.json` que `deduplication.py`.

- **Colonnes MATCHES 1-based** : `_COL_STATUS=11`, `_COL_CV_DRIVE=12`, `_COL_LM_DRIVE=13` — aligné sur le schéma de `test_sheets.py` (`status`, `cv_drive_link`, `letter_drive_link`).

- **`update_matches` non-bloquant** : retourne `False` en silence sur toute exception (job_id absent, API error). L'endpoint `/store-documents` retourne `ok=True` même si l'update MATCHES échoue — les liens Drive sont déjà valides.

- **YAML escaping manuel** : pas de dépendance PyYAML. `_yaml_escape` quote les valeurs contenant `:`, `"` ou démarrant par `#`. Suffisant pour les champs attendus (URLs, noms de companies).

- **Notification Telegram** : `build_telegram_notification` retourne `{text, reply_markup}` prêt pour l'API Telegram. Les callbacks des boutons (apply:yes, apply:no, mark_sent) sont inclus dans la structure mais **non implémentés ici** — Epic 4 Sprint 2.

## Gotchas et contraintes découvertes

- **`noqa: PLC0415`** : ruff signale les imports dans les méthodes comme non-conformes. Ajout de noqa sur chaque import lazy pour conserver le pattern sans désactiver la règle globalement.

- **Drive API scopes** : `https://www.googleapis.com/auth/drive` + `https://www.googleapis.com/auth/spreadsheets` dans `_DRIVE_SCOPES`. Le service account doit avoir accès à ces deux scopes — vérifier dans la Google Cloud Console si les uploads échouent avec 403.

- **`webViewLink` absent si Drive partagé** : `files().get(fields="webViewLink")` peut retourner un dict sans `webViewLink` sur certaines configurations de Drive partagé. Fallback URL : `https://drive.google.com/file/d/{file_id}/view`.

- **Colonne `job_id` = col 1** : `ws.find(job_id)` cherche dans toute la feuille. Si MATCHES a des job_ids dupliqués, `find` retourne le premier. Acceptable pour le cas d'usage (job_id unique par offre).

- **Rate limit `/store-documents` à 10/hour** : sprint spec ne mentionne pas de rate limit. Choix conservateur entre 5/hour (CV/lettre) et 20/hour (form-answers).
