## Décisions clés

### Naming — `openclaw-thehunter.service` (pas `openclaw-hunter.service`)

Le sprint spec mentionne `openclaw-hunter.service` mais `hunter-server.service` (déjà committée sprint 0) déclare `Wants=openclaw-thehunter.service`. J'ai choisi **`openclaw-thehunter.service`** pour cohérence avec l'existant et avec `AGENT_ID = "the-hunter"` dans `hunter_server.py`. Le sprint spec contenait un typo.

### `workspace/openclaw.json` gitignored

Le fichier `openclaw.json` contient le Telegram bot token — il est généré à deploy par `setup.sh` via `openclaw.json.template`. Le template est en git, le json généré est gitignored.

### Stubs pour données personnelles

`CV_BASE.md`, `USER.md`, `GITHUB_REPOS.md` contiennent les données personnelles de Patricia (CV, salaire, préférences). Créés avec structure complète + markers `[FILL IN]`. À compléter avant le premier run du pipeline.

### Tests offline uniquement

`call_hunter` (subprocess openclaw) est mocké. Aucun appel réseau, aucun credential requis en CI.

## Gotchas et contraintes découvertes

- **`description:` frontmatter OBLIGATOIRE** dans chaque SKILL.md ou OpenClaw drop le skill silencieusement. Vérifié par test CI `TestSkillMdFrontmatter`.
- **`hunter_server.py` retourne HTTP 200 même si openclaw échoue** (`ok: false` dans le body). Le test CI couvre ce comportement — il faut vérifier `ok == true` pour une vraie validation fonctionnelle.
- **`openclaw serve` commande à valider sur le VPS** : la commande exacte du daemon openclaw n'a pas pu être vérifiée localement (openclaw non installé sur la machine de dev). Si `openclaw serve` n'est pas le bon flag, ajuster `openclaw-thehunter.service → ExecStart`.
- **Stubs `CV_BASE.md`, `USER.md`, `GITHUB_REPOS.md`** : le skill `cv-rewriter` et `cover-letter-writer` dépendent fortement de ces fichiers. Un first run sans ces données produira un CV générique. À remplir avant d'utiliser les skills Sonnet.
- **Port `openclaw-thehunter`** : aucun port HTTP exposé directement — toute la communication passe par le CLI `openclaw agent` ou le gateway Telegram. Le port 18798 est exclusivement le bridge Python.
- **Validation Telegram** : la validation "Telegram Bot opérationnel" (AC7) est manuelle — envoyer un message test depuis le compte Patricia après déploiement.
