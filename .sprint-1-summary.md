## Décisions clés

### `col_values(1)` chargé une fois dans `_handle_dedup`

`is_duplicate(url_hash, sheet)` appelle `col_values(1)` à chaque invocation — correct pour usage ponctuel. Dans la route `/dedup` (batch de ~60 offres), on charge la colonne une seule fois (`set`) pour éviter 60 appels API successifs. Les deux usages coexistent sans se contredire.

### Ordre des colonnes aligné sur `test_sheets.py`

Le sprint spec nomme les clés dict `url_hash` / `scan_date`, mais le header SCANNED_HASHES réel (défini dans `test_sheets.py`) est `sha256 | date_scanned | url | title | company | source`. La fonction `log_hashes` mappe les clés dict → colonnes dans cet ordre. Pas de renommage des colonnes existantes.

### Bug Merge Branches corrigé (nécessaire pour les sprints suivants)

Sans cette correction, `Scan Output` recevait `{}` (output empty), et tous les nœuds aval du pipeline auraient reçu une liste d'offres vide. Corrigé avec `mode: append` qui concatène les items non-vides des branches actives.

### `deduplication.py` découplé de gspread au niveau module

`gspread` importé en lazy (`open_scanned_hashes` uniquement) — pas d'erreur d'import si gspread absent de l'environnement CI. `TYPE_CHECKING` guard pour les annotations de type `Worksheet`.

## Gotchas et contraintes découvertes

- **`append_rows` vs `append_row`** : gspread a les deux. `append_row` (singulier) = 1 ligne = 1 appel API. `append_rows` (pluriel) = N lignes = 1 appel API. Toujours utiliser le pluriel pour rester dans le quota Google Sheets (300 req/min par projet).
- **Header inclus dans `col_values(1)`** : la valeur `"sha256"` est présente en position 0. Un hash SHA-256 réel fait 64 chars hex — pas de collision possible avec `"sha256"` (6 chars). Pas de traitement spécial nécessaire.
- **Déduplication intra-batch** : si la même URL appear deux fois dans le scan entrant (doublons Indeed/LinkedIn), la seconde est silencieusement ignorée (ajout dans `existing_hashes` local après la première).
- **`GOOGLE_CREDS_PATH` env var** : `deduplication.py` lit `GOOGLE_CREDS_PATH` ou fallback `/opt/apps/job-hunter/credentials.json`. À valoriser en production si chemin différent.
- **Workflow scan_date** : `scanDate` dans le workflow est une string ISO (`2026-06-09T12:00:00.000Z`). La conversion en `dd.mm.yyyy` se fait dans le Code node "Prepare: Dedup Request". Si `scanDate` est absent ou malformé, fallback sur `new Date()` local.
- **Port HUNTER_BRIDGE_PORT** : le nœud "Dedup: Check + Log" utilise `$env.HUNTER_BRIDGE_PORT ?? '18798'`. Si la variable d'env n8n n'est pas définie, le port 18798 est utilisé par défaut (cohérent avec `hunter_server.py`).
