## Décisions clés

- **errorWorkflow plutôt que `continueOnFail` par nœud** : pattern n8n idiomatique — un seul workflow d'erreur réutilisé par les 3 workflows. Plus maintenable qu'un branchement par nœud.
- **CAPTCHA → errorWorkflow** : le scraper exit 1 → Parse LinkedIn Output throw → workflow error → alerte Telegram. Pas de graceful continuation avec les résultats Indeed (spec ne le demandait pas explicitement, "arrêt graceful" = le scraper s'arrête proprement).
- **hunter_bridge self-check sans HTTP** : évite le deadlock sur `http.server` single-thread. Le pont est toujours "ok" s'il répond.
- **Logging fichier uniquement en `__main__`** : les modules de bibliothèque (`health_check.py`) ne configurent pas `basicConfig` — convention Python du projet.

## Gotchas et contraintes découvertes

- `http.server.HTTPServer` est single-thread : appeler `check_hunter_bridge()` depuis le handler `/health` causerait un deadlock. La vérification du pont lui-même est donc auto-reportée `ok: True`.
- `gspread.exceptions.APIError.response.status_code` : pattern `getattr(getattr(exc, "response", None), "status_code", 0)` nécessaire car `response` peut être absent selon la version de gspread.
- `TimedRotatingFileHandler` crée le fichier au premier log, pas à l'initialisation — `os.makedirs` doit précéder pour que le répertoire existe.
- Le test `test_health_returns_200` existant (Sprint 0) continue de passer : le nouveau handler retourne toujours `status: "ok"`, `service: "hunter-bridge"`, `agent: "the-hunter"` — les checks qui échouent (pas de services en test) ne font que setter `ok: False` dans `services[]`.
