# Sprint 2 — Voice Profile Feedback — Résumé d'implémentation

## Ce qui a été implémenté

- **`voice_profile_manager.py`** (nouveau) — module Python pur : `add_feedback`, `remove_feedback`, `list_feedback` opèrent directement sur la section `**Feedback log :**` de SOUL.md. Zéro appel LLM. Chemin configurable via `SOUL_PATH` (env var) ou défaut `/home/thehunter/.openclaw/workspace/the-hunter/SOUL.md`.
- **`telegram_notifier.py`** — nouvelle commande `feedback <add|remove|list> [texte]`. Texte multi-mots réassemblé par `" ".join(argv[2:])`. Date injectée via `datetime.date.today().isoformat()`.
- **`workspace/the-hunter/SOUL.md`** — section `**Feedback log :**` ajoutée à la fin (vide, prête à recevoir des entrées).
- **`workflow-telegram-callbacks.json`** — commentaire du nœud `parse-update` et `meta.notes` mis à jour pour documenter `/feedback`. Aucun changement de logique requis : le nœud strip déjà le `/` et passe le reste en `commandArgs`.
- **`tests/test_voice_profile_manager.py`** (nouveau) — 34 tests unitaires couvrant add/remove/list + intégrité fichier.
- **`tests/test_telegram_notifier.py`** — 9 tests ajoutés (`TestFeedbackCommand`).

## Décisions clés

- La section est délimitée par la ligne exacte `**Feedback log :**` (non un heading `## `), conformément au format du sprint. Fin de section = prochain heading `## ` ou fin de fichier.
- `remove_feedback` supprime la **première** occurrence contenant le texte cible (substring match). Comportement documenté dans les tests.
- SOUL.md n'est jamais écrasé : `_split_soul` décompose en `(prefix, entries, suffix)` et réassemble chirurgicalement.
- Le chemin SOUL.md en production est hardcodé dans `voice_profile_manager._DEFAULT_SOUL_PATH` ; `SOUL_PATH` n'est exposé qu'en test — pas de changement sur le nœud n8n `run-notifier`.

## Gotchas et contraintes découvertes

- Le workflow n8n ne nécessite **aucune** modification de routing : il passe déjà `commandArgs` stripped du `/` au script Python. La commande shell reçoit `feedback add "text"` correctement.
- Si Patricia écrit `/feedback add texte sans guillemets`, le shell split les mots et `" ".join(argv[2:])` les réassemble — fonctionne sans guillemets Telegram.
- `**Feedback log :**` avec un espace avant `:` est le format du sprint. La détection utilise `.rstrip()` pour tolérer un espace trailing sur la ligne mais pas un espace dans le marker lui-même.
- SOUL.md dans le worktree (`workspace/the-hunter/SOUL.md`) est la copie repo ; la production est `/home/thehunter/.openclaw/workspace/the-hunter/SOUL.md`. Les deux doivent être synchronisés lors du déploiement.
