# Sprint 2 — Écriture SCANNED_HASHES + MATCHES — Résumé d'implémentation

## Ce qui a été implémenté

- **`pipeline_writer.py`** (nouveau) — CLI wrapper autour de `prioritizer.run_prioritizer` : lit JSON depuis stdin (`{new_matches: [...]}`), ouvre les deux sheets gspread, appelle `run_prioritizer`, sort le résultat JSON sur stdout. Appelé par n8n via `executeCommand`.
- **`workflow-main-pipeline.json`** — remplacement du nœud cassé "Prioritize Matches" (POST `/prioritize` inexistant dans `hunter_server.py`) par 5 nouveaux nœuds en séquence :
  1. **Filter: Extract LinkedIn** (Code) — split `new_offers` en `linkedin_offers` + `indeed_offers`
  2. **Layer1: Filter LinkedIn** (HTTP POST `/layer1`) — filtre disqualifiants sur les offres LinkedIn uniquement
  3. **Layer2: Score LinkedIn** (HTTP POST `/layer2`, threshold=0.6) — calcul match_rate pour LinkedIn
  4. **Qualify: Merge + Prepare** (Code) — Indeed qualifiés (match_rate ≥ 60% depuis CSV) + LinkedIn high_match (0-1 → % normalisé), job_id SHA-256[:16], date ISO, payload base64
  5. **Write: Matches + Pending** (executeCommand → `pipeline_writer.py`) — cap 25 via `run_prioritizer`
- **`tests/test_main_pipeline.py`** — 29 nouveaux tests (5 classes AC1–AC5), 68/68 pass :
  - `TestAC1IndeedMatchRatePreserved` — `write_match_if_qualified` écrit le score CSV verbatim
  - `TestAC2LinkedInMatchRateWritten` — LinkedIn ≥ 60% écrit, source/status/format corrects
  - `TestAC3BelowThresholdNotWritten` — < 60% absent de MATCHES, frontière exacte = 60
  - `TestAC4DeduplicationFilters` — `is_duplicate`, `log_hashes`, ordre colonnes SCANNED_HASHES
  - `TestAC5Cap25PendingMatches` — `run_prioritizer` : 30 qualifiés → 25 MATCHES + 5 PENDING

## Décisions clés

- **`/prioritize` n'existe pas dans `hunter_server.py`** : l'ancien nœud Sprint 1 était cassé silencieusement (404). Résolu via `pipeline_writer.py` (nouveau fichier, pas de modification de `hunter_server.py`).
- **Séparation des sources dans le workflow** : Indeed et LinkedIn suivent des chemins distincts (Indeed bypass Layer1/2, LinkedIn passe par les deux). Fusion dans le Code node "Qualify" avec normalisation de l'échelle match_rate (0-1 → %).
- **`_score_offer` (hunter_server) vs `compute_match_rate` (layer2_scoring)** : deux fonctions de scoring avec des échelles différentes (0-1 vs 0-100). Layer2 HTTP renvoie 0-1 → le Code node multiplie par 100 avant write.
- **job_id LinkedIn** : SHA-256(normalize_url(url))[:16] calculé dans le Code node JS via `require('crypto')`, cohérent avec la convention 16 chars du projet.
- **Payload base64** : l'executeCommand reçoit le JSON des offres via `echo '<b64>' | base64 --decode | python3 pipeline_writer.py` — évite les problèmes d'échappement et la dépendance à `require('fs')` dans les Code nodes n8n.

## Gotchas et contraintes découvertes

- **`hunter_server.py` `/prioritize` manquant** : le nœud "Prioritize Matches" de Sprint 1 référençait un endpoint inexistant. N'a jamais fonctionné. La contrainte "ne pas modifier hunter_server.py" implique de contourner via un CLI Python externe.
- **Deux fonctions de scoring avec échelles incompatibles** : `_score_offer` (hunter_server) retourne 0-1 ; `compute_match_rate` (layer2_scoring) retourne 0-100. Les tests Sprint 2 utilisent `write_match_if_qualified` qui attend 0-100. Le workflow normalise correctement avant write.
- **`_handle_write_scan_results`** dans hunter_server.py écrit TOUTES les offres dans MATCHES ET PENDING_MATCHES sans cap — ne pas utiliser pour l'écriture finale (utiliser `pipeline_writer.py` + `run_prioritizer` à la place).
- **`$('Filter: Extract LinkedIn').first().json`** dans le Code node "Qualify" : n8n permet de référencer des nœuds antérieurs par nom, ce qui est nécessaire ici car `indeed_offers` disparaît après le passage par Layer1/Layer2 HTTP.
- **Sprint suivant (Sprint 3 — Notifications Telegram)** : `run_prioritizer` écrit les offres dans MATCHES avec `status="Notifié"` et `telegram_sent="FALSE"` via `_build_matches_row`. Le champ `status` dans les offres entrantes (="new") est ignoré par `_build_matches_row` qui force "Notifié". Le Sprint 3 devra utiliser `matches_sheet.find` + `update_cell` pour déclencher les notifications Telegram.
